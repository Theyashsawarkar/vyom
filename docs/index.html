Vyom (व्योम) is Sanskrit for "sky": the space everything sits in.

Vyom replaces wofi in Vayu. Instead of scripts piping text rows into a generic list, each job is a tool: a small plugin with real layouts, live data, previews, toggles and a key for everything. Vyom is what they run in: one resident process with a shared panel, theme and plugin API, so every tool opens instantly and looks the same.

#Install

Requirements: Python 3.11+, PyGObject (with pycairo, for tools that draw), GTK 4, gtk4-layer-shell, a compositor with the layer-shell protocol (sway, Hyprland, river, Wayfire, labwc…), and a Nerd Font for the icons.

# Arch
sudo pacman -S --needed python-gobject python-cairo gtk4 gtk4-layer-shell ttf-jetbrains-mono-nerd

git clone https://github.com/Theyashsawarkar/vyom ~/.local/share/vyom/core
ln -s ~/.local/share/vyom/core/bin/vyom ~/.local/bin/vyom

# then the tools you want, e.g.
git clone https://github.com/Theyashsawarkar/dvara ~/.local/share/vyom/plugins/dvara
git clone https://github.com/Theyashsawarkar/ganit ~/.local/share/vyom/plugins/ganit

In your compositor (sway shown):

exec vyom daemon                      # start it in the background at login
bindsym $mod+d exec vyom dvara        # each tool on its own key; again closes it
bindsym $mod+c exec vyom ganit
layer_effects "vyom" {                # SwayFX: blurred glass behind every panel
    blur enable
    corner_radius 20
    shadows enable
}

#Usage

vyom <tool> [args]        open a tool (e.g. vyom tarang, vyom raga video); again closes it
vyom dmenu [-p PROMPT] [--markup] < lines
                          pick one line: printed on stdout, exit 1 on Esc (like wofi --dmenu)
vyom list                 installed tools, and why one is skipped
vyom daemon | reload | quit
vyom quick                quick settings (the kendra tool)

Vyom keeps one resident process (a GTK single-instance app). Once it's running, vyom <tool> only sends it a D-Bus message, so a panel opens in well under a tenth of a second. vyom dmenu makes any script's picker a Vyom panel: printf 'Accept\nReject\n' | vyom dmenu -p "Pair?".

Every panel: type to search, Up/Down (or Ctrl+K/Ctrl+J) move, Page Up/Page Down jump, Enter runs, Esc closes. A tool's tabs are its main kinds (ganit's Calculate and Convert, tarang's Networks and Hotspot), shown by name and switched the same way everywhere: Tab / Shift+Tab (or Ctrl+L/Ctrl+H) for the next/previous tab and Ctrl+1..9 (Ctrl+0: the tenth) by place, which each tab's tooltip says. A tool opens from its own key; Tab never leaves it for another tool. Each tool adds its own keys (shown in its footer and README).

KeyAction
Up / DownMove to the previous / next result
Ctrl+K / Ctrl+JMove to the previous / next result
Page Up / Page DownJump a page of results
EnterOpen or run the selected result
Tab / Shift+TabSwitch to the next / previous tab (tools with tabs; wraps around)
Ctrl+H / Ctrl+LSwitch to the previous / next tab (tools with tabs)
Ctrl+1..9Switch to the first..ninth tab (Ctrl+0: the tenth; its tooltip says which)

On a card (the power menu, quick settings, the battery), Space never presses the focused button; Enter does.

#Vim keys

A tool written for them (modal = True, ADR 8) has vim's modes instead: in NORMAL mode every key is a command and typing changes nothing; in INSERT mode keys type (Esc goes back). The footer shows the mode, the keys typed so far and this mode's keys; after Space (or any prefix) a strip shows what comes next. The same keys work in every such tool:

KeyAction
j / kMove down / up (a count first moves further: 5j)
g g / GJump to the first / last result (5G: the fifth)
Ctrl+d / Ctrl+uScroll half a page down / up
H / LSwitch to the previous / next tab (Tab, Ctrl+H/L still work)
/Search again: clear the box and type
iType in the search box (insert mode)
EnterOpen or run the selected result
qClose the panel
EscCancel a pending key, then clear the search, then close
?Show every key of this view
Space SpaceOpen the palette: every action here, type to filter, Enter runs
Space ?Show every key of this view
Space qClose the panel
Space t <initial> / Space t 1..9Switch to a tab
Space u fToggle fullscreen (F11 too)
Space rReload what the panel shows

In insert mode: Esc back to normal, Ctrl+J/K move the results, Enter runs. On a card: j / k move between its controls, h / l move a slider (else left/right), 0 / $ its minimum/maximum, Enter toggles or opens. A question (deleting something) takes y for yes; any other key keeps things.

The Space groups mean the same in every tool, so a tool may leave one empty but never use its letter for something else: Space palette, ? keys, q close, t tabs, u toggles, y copy, f find, s sort, r refresh, a add, d delete, e edit, o open outside, g go to, m mark, , settings, k ask AI. A tool's own groups use the other letters (b c h i j l n p v w x z).

#Configuration

~/.config/vyom/config.toml, all optional (examples/config.toml):

[vyom]
disabled = ["raga"]          # installed tools not to load
width = 900                  # every panel opens at this size (times scale = 1.25)
height = 520
opacity = 0.72               # panel background: 1 solid, lower = more glass
css = ["~/.local/state/varna/vyom.css"]   # more stylesheets, loaded last (a theme's colours)

[plugin.tarang]              # each tool's settings: see its README
hotspot_command = "vayu-hotspot"

~/.config/vyom/style.css loads after the tools' styles, to restyle anything; the css files load after that. Colours are named (@base, @text, @accent, @mauve...: Catppuccin Mocha by default), so a theme only has to redefine them: varna writes such a file.

#Writing a tool

A tool is a directory with a plugin.toml and a Python package of the same name exporting a Plugin class:

# plugin.toml
name = "hello"
title = "Hello"
version = "0.1.0"
vyom = "0.2"
icon = "󰞅"          # Nerd Font glyph for the mode pill
color = "mauve"     # sky blue teal red peach mauve yellow green rose lavender
requires = []       # tools it needs; it's skipped (with the reason) without them
# hello/__init__.py
from vyom import Hint, Plugin as Base, Row, Section, ui, util

class Plugin(Base):
    preview = True                       # a preview pane on the right
    hints = [Hint("Enter", "greet")]
    tabs = [("people", "People"), ("places", "Places")]   # optional: Ctrl+H/L, Ctrl+1..9

    def search(self, query):             # runs in a worker thread
        return [Section("People"), Row("World", "the usual", icon="󰞅", data="world")]

    def build_preview(self, row):        # main thread
        return ui.vbox(ui.title(f"Hello, {row.title}"), ui.meta("a preview"))

    def activate(self, row, mods):       # Enter; return True to close
        util.notify("Hello", row.data)
        return True

Layouts: "list" (rows, sections, preview), "grid" (cells, like the emoji picker) and "card" (build the whole panel in build_card()). A list can show a status strip above its rows (build_strip(): what's connected, what needs you), and a Row can carry coloured chips and signal bars (level, level_text, level_color). vyom.ui has the shared pieces: hero, ring, bars, meter, steps, notice, segmented, and buttons that show their key (ui.button("Forget", forget, "danger", key="Ctrl+F")), and an on/off ui.switch for a header. The footer shows hints, or tab_hints() when the keys differ by tab (or mode); a set_status("…") message takes their place while it shows, so it's never cut short. See vyom/plugin.py for every hook (tabs with self.tab, tab_changed and select_tab; header_extra, key, opened, closed, live, anchor…), vyom/ui.py for widgets, and any tool repo for a worked example. Put it in ~/.local/share/vyom/plugins/hello (or a directory in $VYOM_PLUGIN_PATH) and vyom reload.

#Vim keys in a tool

Set modal = True and return the tool's keys as data from keys(tab); the panel does the modes, counts, sequences, which-key strip, help and palette:

from vyom.keys import Bind

class Plugin(Base):
    modal = True
    start_mode = "insert"                # a search-first tool; "normal" for one you manage things in
    key_groups = {" c": "container"}     # names for the tool's own Space groups

    def keys(self, tab):
        return [Bind("dd", "remove", "Remove the container (asks first)"),
                Bind(" cr", "restart", "Restart the container"),
                Bind(" yy", "copy", "Copy the name")]

    def v_remove(self, count, arg):      # an action "verb:arg" runs v_<verb>(count, arg)
        row = self.panel.selected_row()
        self.confirm(f"Remove {row.title}?", lambda: ...)

A bind with the same keys as one of the panel's replaces it. A card lists its text boxes in editables() (they type only in insert mode); escape() takes Esc first (unpick something); mode_hints(mode) gives the footer's keys per mode; key() still sees every key first, for a tool's own overlay. vyom.keys.annotations() writes the # keybind: lines from the same binds (ganit's scripts/keybinds.py is an example). The panel also gives every modal tool Space u p (show or hide the preview, remembered per tool) and, on a card, a visible cursor on the focused control; a tool can add a side rail left of its results with build_rail() (tabs_in_rail = True when the rail shows its tabs). Python tools outside Vyom vendor the keys module with scripts/vendor-keys.sh <file>.

#Troubleshooting

  • A tool doesn't open. vyom list shows every installed tool and why one is skipped (a missing requirement, or a Vyom too old for it).
  • Something failed. The daemon logs to the journal: journalctl --user -u vyom -u vyom-daemon -b (without systemd: ~/.local/state/vyom/daemon.log); look for a Traceback. vyom quit; vyom <tool> restarts it.
  • "Failed to initialize layer surface" / panels open as normal windows. gtk4-layer-shell has to load before GTK; vyom daemon does this itself through LD_PRELOAD, so start Vyom with vyom daemon, not python -m vyom.app.
  • No blur or rounded corners. That's the compositor's part: on SwayFX use the layer_effects "vyom" block above; Hyprland: layerrule = blur, vyom.
  • Icons show as boxes. Install a Nerd Font.
